# Translations (i18n)

UI text in English and Hebrew, with right-to-left layout. The language is a per-device choice from the picker in the top bar (and on the welcome screen); the first visit follows the browser language.

## Files Covered

| File | Purpose |
|------|---------|
| `locales/en.ts` | English strings; its keys are the `MessageKey` type |
| `locales/he.ts` | Hebrew strings plus SRD term names |
| `locales/explain.en.ts`, `locales/explain.he.ts` | Builder option explanations (`why.<kind>.<id>`), spread into `en` and `he` |
| `locales/explain.books.en.ts`, `locales/explain.books.he.ts` | Explanations for warlock patrons from official books outside the SRD (short original summaries), spread into `en` and `he` |
| `locales/explain.classes.en.ts`, `locales/explain.classes.he.ts` | The same for every other class's book subclasses. A feature name that means different things in different subclasses (Divine Strike, Bonus Proficiencies) gets `why.subfeature.<subclassId>.<name>`; look keys up with `featureKey(name, subclassId)` from `builder/why.ts` |
| `locales/items.en.ts`, `locales/items.he.ts` | Item editor "why?" text for every field and effect (`inv.why.*`, `inv.whyfx.*`) and the newer effect kinds, spread into `en` and `he` |
| `translate.ts` | Pure `translate()` (vars, plurals, English fallback), `term()`, `LOCALES` |
| `store.ts` | Current locale, saved in `ff.locale.v1`, mirrored to `<html lang dir>` |
| `useI18n.ts` | Hook: `t`, `term`, and helpers `className`, `raceName`, `ability`, `abilityShort`, `skill`, `item`, `attackName`, `classLine`, `date` |
| `LanguagePicker.tsx` | The language `<select>` |
| `i18n.css` | Picker style and RTL fixes for signed numbers and dice notation |
| `i18n.test.ts` | Lookup, plural and Hebrew coverage tests |

## Adding UI text

1. Add the key to `locales/en.ts` (namespace by screen: `sheet.*`, `party.*`...) and to `locales/he.ts`. The coverage test fails if Hebrew is missing a key.
2. In a component: `const { t } = useI18n()` then `t('party.dm', { name })`. Outside React use `t` from `store.ts`; pure code takes a `Translate` argument that defaults to English (see `builder/validate.ts`).
3. Plurals: add `key_one` (and `key_two` for Hebrew) next to `key`, and pass `{ count }`.

## SRD names

Data files stay English. Display names go through `term(kind, id, englishName)`, keyed `race.<id>`, `class.<id>`, `skill.<id>`, `item.<id>`, `resource.<id>`, `condition.<id>`, `ability.<a>`, and by English name for `feature.`, `trait.`, `language.`, `alignment.`. Anything missing (homebrew, new gear) shows the English name. Saved values (alignment, labels) are never translated.

## Right-to-left

Write CSS with logical properties (`margin-inline-start`, `text-align: start`, `inset-inline-end`), never `left`/`right`. Elements that show signed numbers or dice notation need `direction: ltr; unicode-bidi: isolate` under `[dir='rtl']` (listed in `i18n.css`), or `dir="ltr"` on the element. Arrow glyphs come from strings (`common.backArrow`, `builder.next`) so they flip with the language.

## Adding a language

Add `locales/<code>.ts` exporting `{ messages, terms }`, register it in `LOCALES` and the `Locale` type in `translate.ts`. Missing keys fall back to English.

## Not translated yet

Messages produced outside the UI stay English: rules-engine warnings, dice notation errors, import validation errors, homebrew entry checks and feat effect summaries (`homebrew/pack.ts`), change-history notes and field names, and default roll labels from `dice/character.ts`. Sheet log entries keep the language they were made in.
